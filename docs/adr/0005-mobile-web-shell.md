# ADR-0005: Web/Desktop 移动适配先抽共享外壳再修页面

- status: accepted
- date: 2026-10-03

## 背景

DENE-1277 的全站盘点发现，返回栈、侧滑返回、安全区、触屏尺寸和窄屏承载同时影响多个共享页面。`packages/views/` 被 Web 与 Desktop 共用；如果每个页面族各自修一套，覆盖层和返回行为会逐渐分叉。原生 `apps/mobile/` 是独立客户端，不与这次 Web/Desktop 页面族修复混在一起。

## 决策

1. Web/Desktop 的移动共性先在共享外壳和基础组件中统一承载，再由页面族子票处理页面特有的布局、返回来源和状态保留问题。
2. 移动适配以 375px、768px、1280px 三档真实浏览器核验为共同验收边界；静态 CSS 推断不单独作为修复结论。
3. 页面族交付保留修复前后截图和 HTML 预览，父票在所有子票完成后按同一三档边界复验；原生手机 App 继续按自己的客户端边界交付。

## 理由

- 共享外壳可以一次收口返回栈、安全区和触屏承载，避免同一交互在不同页面出现不同表现。
- 固定三档并要求真实浏览器证据，能把“代码看起来支持”与用户实际可用区分开。
- 页面族仍保留独立节奏，页面特有问题不会被共性组件塞进一套无法解释的规则。

## 后果

- 新的 Web/Desktop 页面适配应先检查共享外壳能力，再决定是否需要页面层改动。
- 子票和父票都需要以截图或等价的真实浏览器证据说明三档结论；未走查的页面保持待核验状态。
- 修改移动共性时要同时关注 Web 与 Desktop；原生手机 App 的同名入口不自动继承这份决定。
