# ADR-0008: 档位与派单模式是两个正交概念

- status: accepted
- date: 2026-10-08

## 背景

路由原来用一个字段回答两个问题：`routing_tier` 既说「这个席位多强」，也暗含「这个席位参与自动派单」——只要标了档位，席位就进了自动派单池。像拉蒂兹这种「弱模型、只该被点名或委派、绝不自动派」的席位因此表达不出来：挂上弱档就被当成普通弱档席位自动选中（DENE-1539：弱档票派给拉蒂兹，连跑两次 501 空转）。

同时，「这个席位此刻能不能被自动选中」在三处各写了一遍：初始派单（`routing.SceneCandidates`）、额度接力换人（`service/quota_relay.go`）、席位中转（`handler/seat_relay.go`），条件互有出入。

## 决策

1. **标了档位 ≠ 进自动派单池。** `routing_tier` 只表示强度。新增 `agent.dispatch_mode`：`auto`（默认，参与自动派单）/ `mention_only`（能被点名、指派、委派，永不被自动选中）。
2. **与 `work_enabled` 正交。** `work_enabled=false` 是连点名都不接；`mention_only` 是能接，只是不自动塞。拉蒂兹 = 弱档 + `mention_only` + 开工。
3. **判断收在一个模块。** `routing.SeatSelectable(state, ctx) → (ok, reason)` 一处判完归档、停用、运行时、派单模式、档位、可用性和额度熔断。初始派单、额度接力、席位中转、同档替补都调它，不再各写一份。
4. **在候选集这一层滤掉。** `mention_only` 席位不进 `SceneCandidates`，判断模型看到的名单里没有它，简报不因它变长。名册（`Roster`）仍收录它，所以它当执行人或验收人时的叫醒、升级、交棒照常。
5. **派单模式随档位一起跟随底座。** 跟随底座的特化席位继承底座的档位、用量和派单模式，三者是同一组路由配置。

## 理由

- 一个字段一个意思，人改档位时不会顺带改掉「要不要自动派」。
- 用 deletion test 看，自动可选判断删掉后复杂度会在三处各自重现，所以它该是一个模块；收拢后加一个条件只改一处，三条路径同时生效。
- 在候选集过滤而不是在判断后过滤：模型从没见过的席位不会被它选中，也不用再写「选中了再退回」的分支。

## 后果

- 新的自动选派路径必须经过 `SeatSelectable`，不能直接读 `work_enabled` / `routing_tier` 自行判断；矩阵测试钉住 `mention_only` 在三条路径都不被选中。
- 点对点路径（@ 提及、指派、委派、叫醒现任执行人或验收人）不看 `dispatch_mode`，只看 `work_enabled` 与归档。
- 要再加一种派单模式（例如「只做验收」），改 `dispatch_mode` 的取值和 `SeatSelectable` 一处即可。
