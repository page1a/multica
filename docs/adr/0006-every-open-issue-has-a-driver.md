# ADR-0006: 每张未关闭的票都有驱动者

- status: accepted
- date: 2026-10-04

## 背景

DENE-1312 的运行在建工作树时撞上宿主机的瞬时写失败（`unable to write file …`，随后 `Could not reset index file`），被归为不可重试的 `environment_prepare_failed`。这次运行是从聊天派出来的：委派失败恢复找不到可以回去的协调票，通知父票的逻辑又因为它“是委派的”而跳过。结果子票停在 `todo`，没有运行、没有等待、也没有人，父票 DENE-1311 什么都没收到。

## 决策

1. **驱动者只有三种**：活着的运行、平台记下且到点检查的等待、被点名的人。每张未关闭的票任何时刻至少有一个。
2. **瞬时的检出失败先就地重试。** 守护进程在同一仓库锁内对 `git worktree add` 最多再试两次，每次之间清掉半成品工作树和分支。服务端把文本里带这类迹象的 `environment_prepare_failed` 当作可重试，停 30 秒再排一次。判断依据是失败文本而不是新增失败原因，这样没升级的守护进程也能拿到重试，也不用在五种语言和移动端加新文案。
3. **没有排上重试的失败只走一个出口。** 不管是不是委派的，只要委派恢复没有接住，服务端就把智能体负责的 `todo` / `in_progress` 票（或叫醒时间已经过了的 `blocked` 票）转为 `blocked`，写入失败叫醒时间（0 / 5 分钟 / 15 分钟 / 1 小时 / 4 小时退避），由巡检到点叫醒执行人。人负责的票、未指派的票、`in_review` 和已关闭的票不动；已经记了仍有效等待的票不覆盖。
4. **父票通知只承诺真实存在的东西。** 写下了叫醒时间才说“到点会重新叫醒”；没写就直说平台没有排上重试或叫醒。

## 理由

- “谁在推进这张票”必须能从票上读出来，不能靠人巡视看板发现停摆。
- 文本判定的代价是要维护一份 git 报错片段清单；换来的是不改协议、不改界面、老守护进程同样受益。
- 复用巡检的失败退避而不是立即重跑，避免同一个坏环境每分钟被叫醒一次。

## 后果

- DENE-1342 补齐了后半段：服务端在 `issue get` / `issue children` 上算出 `driver`（`run` / `wait` / `person` / `none`）；巡检看到被等的票或零运行的 `todo` 票没有驱动者时，先在原席位重跑，24 小时内最多 2 次，仍停着就上报一次，叫醒父票负责人（没有父票或父票是成员时点名人）；父票负责人用 `multica issue dispose`（重跑 / 换人 / 拆分 / 取消）处置，界面上同一行可点。运行时超时走巡检清理路径的失败也改为转 `blocked` 并记下失败叫醒时间，不再退回 `todo`。
- 新增会让运行终止的路径，要么排上重试，要么经过同一个出口；不要再各自决定要不要留驱动者。
