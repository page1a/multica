# ADR-0001: 统一带选项提问

- status: accepted
- date: 2026-10-01

## 背景

目标模式、需求对齐和日常协作都需要在推进过程中向人请求明确选择。此前各入口可能各自承载提问和回答，容易造成校验、提醒和回答状态不一致；同时智能体需要在没有浏览器的情况下发问和读取结果。

## 决策

采用一个由服务端持有的带选项提问作为跨界面的共享契约。提问由一个提问者创建，可以关联任务，包含一组问题和有限选项，并区分“需要你”和“顺手问”两种等待语义。任务动态、聊天、收件箱和 `multica ask` 都读取并回答同一提问对象。

## 理由

- 服务端统一校验问题、选项、推荐项和回答状态，避免各入口出现不同规则。
- 所有界面展示同一个提问对象，回答状态和唤醒提问者的行为保持一致。
- CLI 与界面共享同一接口，智能体可在无浏览器时完成发问、查询和回答。

## 后果

- 新的需要人作选择的流程应复用带选项提问，而不是另建一套入口专用状态。
- 新增入口需要同时接入服务端契约和现有的任务动态、聊天、收件箱展示路径，并同步 CLI/平台技能说明。
- 提问协议成为跨服务端、Web/Desktop 和 CLI 的长期边界；若未来修改，需要同时评估三面兼容性。
